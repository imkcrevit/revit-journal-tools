# 基础架构

目标是先建立可追溯的读取、识别、报告链路，随后用真实案例推动扩展。

```text
Journal文件 → 严格解码与逐行读取 → 规则匹配 → 候选、上下文、统计 → CLI报告
                         ↓             ↑
                   记录分类与磁盘索引   人工复核案例与回归测试
                         ↓
                段落/事件分组 → CLI终端查看器 → 分类、检索、折叠/展开
                         ↓
                原有Web查看器 → 逐行列表与上下文
```

`JournalReader`通过单个打开的文件流读取并计算原始字节SHA-256。编码按文件决定：`auto`先看BOM，再用增量解码器对整文件做严格预检（UTF-8，然后系统ANSI代码页的严格超集，cp936映射为gb18030），选中第一个能完整解码的候选后再逐行读取；预检只解码不分行，6.47MB文件约30ms。所有候选都失败时进入退化模式：按最后一个候选读取，注册的错误处理器把每个无法解码的字节暂存为U+DC00–U+DCFF的孤立代理（严格解码器不会产生它们，且不吞掉换行字节，行号不变），逐行替换成可见的`\xNN`并标记`degraded`，计数与前20个行号进入报告与索引。显式单个编码保持严格模式，失败即整文件失败。文件读取前后核对大小、修改时间、文件标识以及实际读取字节数；此检查用于发现常见的并发修改，不是文件系统快照。失败时不把部分结果包装成完整扫描。

`sessions.py`只按文件名和所在目录把输入归为Revit会话（`journal.NNNN`前缀），角色为主Journal、Worker、精简、副本、dmp或未识别命名。大小相同的文本输入会计算SHA-256，字节相同者只保留一个（优先主Journal），其余作为`duplicate`旁注；0字节文件为`empty`，`.dmp`为`binary`，两者都不进入索引队列，但在会话中列出。

`Rule`是声明式JSON规则。每条规则在每行最多产生一次命中，所有匹配位置均使用解码后的字符索引，不是原始字节偏移。规则不执行Journal内容、不运行Python代码，不访问网络。规则正则应由项目维护者审核，当前没有正则执行超时隔离；加载时`regex_safety.py`拒绝可重复组内与后续字符重叠的无界量词（如`(a+)+`），多项式级回溯不检查。规则可声明字面量门控`gate`：`match_rules`每行只折叠一次（`rules.fold`：小写，并把正则忽略大小写时等同于i/s的`İ ı ſ`先换掉），门控子串都不在行内时跳过该规则的正则。门控是必要条件，不改变命中；内置规则全部声明了门控，测试与`scripts/verify_equivalence.py gates`逐行证明有无门控命中相同。

分类与分段沿用同一思路：`Categorizer`、`BlockBuilder`、`LoadingEvidence`中每个忽略大小写的正则前都有按`fold`检查的字面量门控（模块级`*_GATE`元组），每行的形状判断（时间戳、API头、资源采样、强错误、加载前缀、原生异常）只计算一次；`LoadingEvidence`未激活时只检查加载前缀门控。`tests/test_categories_gates.py`把全部门控替换为空串（即总是运行正则）后比对分类与块，结果必须完全相同。约一半的Journal行与前面某行文字相同：`Categorizer`在API_ERROR花括号外按（文字，两个续行状态）缓存结果与下一状态，`BlockBuilder`按文字缓存`_shape`算出的全部纯文字特征，两者各有16,384条上限；测试比对缓存、极小上限和不缓存三种结果。

`analyze`只持有当前行、有限长度的前文、正在补齐后文的候选，以及有容量上限的明细和重复组。总计数不受明细上限影响。同一行多个规则合为一个候选，级别取最大值；分组只对完全相同的行内容和命中规则集合生效。

明细通过有界堆按严重级别优先保留，同级保留较早出现的候选。文件末尾的严重错误可替换早期警告，并保留其原文和上下文；报告按实际行号展示。重复分组单独计数，分组容量仍按首次出现顺序分配。

内存规模主要与单行长度、明细容量、上下文长度、片段长度和分组容量有关，不随文件总字符数线性增长。JSON转换会临时复制当前文件的有限报告对象；批量导出按文件顺序写出，不在内存堆积所有文件报告。

`ScanReport.schema_version`为1。来源哈希、规则集哈希、工具版本与扫描配置共同描述一次分析的输入条件。`status=ok`和`scan_complete=true`表示读取扫描成功；`assessment=rule_candidates_only`与候选的`status=candidate`描述判断范围。

CLI在扫描前发现文件，对单个文件失败进行隔离。输出先写同目录临时文件，成功关闭后原子替换目标；Journal和自定义规则文件禁止作为输出目标，包含符号链接和硬链接别名。

`BlockBuilder`根据时间戳、空白、API花括号、操作续行、资源采样和异常续行建立连续行号范围。只保存当前块元数据，完整原文复用`lines`表；`blocks`表保存范围、类别、有限标题、规则与边界是否闭合。每个原始行恰好属于一个块，显示分页不会改变分组。`ViewerIndex.blocks`将FTS命中行映射回所属段落并去重，展开时通过`block_lines`按页读取。

`LoadingEvidence`在明确的Add-in加载事件中累计Vendor依据，直到整个块结束才确定来源。跨行字段缓冲最多4096字符，依据最多8条、每条400字符；不根据DLL路径推断厂商，不继承上一个事件的Vendor。`blocks.addin_origin/addin_evidence`保存独立来源属性，原有错误分类与级别保持有效。CLI用`BLOCK_FILTERS`将来源筛选映射到独立索引字段，FTS仍先找命中行，再映射为完整块。分类统计包含可重叠的来源计数，总块数只累计原有互斥类别。旧数据库自动补充字段，`BLOCK_VERSION`变化触发已选文件重建。

加载事件正文先剥离时间戳、Journal层级和API包装，再检查正文开头的固定加载前缀。`addin_name/addin_class`各保留最多512字符，超限由`addin_identity_truncated`标记；字段可跨行，但不跨事件继承。名称/Class前缀通过带转义的SQL前缀查询筛选，支持与来源及FTS组合，并保留原始起始行分页游标。CLI折叠列表只使用这些元数据；Add-in条目忽略普通段落预览级别，仅在展开时调用`block_lines`读取原文。

`ViewerIndex`写入：每个文件一个事务。先在短事务中删除旧行（同时用`'delete'`命令删除其FTS条目）并标记`indexing`；随后`parse_into`按2万行一批`executemany`写`lines`与`blocks`，文件读完后在同一事务内用`INSERT INTO line_search(rowid, body) SELECT ...`一次性建立该文件的全文索引，再写统计并置`ready`。失败或停止时整个事务回滚，不会留下半个文件。旧版本逐行维护FTS的触发器在打开数据库时删除；“`lines`中每一行都有FTS条目”的不变式由同事务插入/删除保证。连接保持`synchronous=NORMAL`（WAL模式下提交不刷盘，只在检查点刷盘）。

多文件时（至少2个文件、总量不小于`PARALLEL_MIN_BYTES`=2MB），`ViewerIndex`用`multiprocessing`的`spawn`上下文启动进程池：子进程各自加载内置规则，把一个文件解析进系统临时目录中的私有临时库（无索引、无日志），返回元数据；主进程按完成顺序`ATTACH`临时库并以`INSERT ... SELECT`复制，FTS与状态更新同上。只有主进程写共享索引，子进程不持有任何主进程连接。停止时终止进程池，未复制的文件保持`queued`。

CLI的`browse`命令调用同一索引，提供颜色和折叠交互，不启动HTTP服务。`scan`继续提供逐行错误候选报告，原有`view`保留Web列表。三种入口共享原始行号和解码规则；块数、命中行数和实际事故数不能混为一谈。

扩展入口：

- 新错误线索：优先增加JSON规则和来自案例的回归测试。
- 跨行异常、会话结构：扩展`blocks.py`中的有状态分段，保留原始行映射和边界依据。
- 本地界面：已使用同一读取器和内置规则建立全量索引；可继续扩展文件导入、任务管理和操作阶段。
- AI辅助判断：只消费可追溯候选及相关上下文，输出独立结论与依据，不修改原始证据。

框架不依赖Revit、MCP、revitrag或外部模型服务。当前仅对离线文本处理负责，真实Revit运行和真实案例识别率另行验证。
