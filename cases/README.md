# 案例接收

可以在框架开发期间持续添加案例。原始Journal放在`cases/inbox/`，按案例建子目录即可：

```text
cases/inbox/case-001/
  journal.0001.txt
  case.json
```

`case.json`可从`cases/case-template.json`复制，只是人工登记模板，当前CLI不会自动读取或验证它。未知字段可保留`null`，不需要为了提交案例补齐所有信息。

建议一起提供：Revit版本、出问题前的操作、实际现象、预期结果、近似发生时间。完整Journal有助于保留上下文；只提供片段也可以，但行号对应片段本身，不能当作原文件行号。

扫描已收到的全部案例：

```bash
revit-journal scan cases/inbox --recursive --format json -o reports/cases.json
```

一次扫描使用启动时发现的文件清单。扫描期间新添加的文件会在下次运行处理，不做后台监听。

原始案例和输出报告默认被Git忽略，工具本身不发起网络请求。需要去标识化时另存副本，保留原始文件，不把改写副本的哈希当成原始文件哈希。

每个案例到来后的处理流程：

1. 保留原文件，记录字节哈希、编码与扫描配置。
2. 核对预期错误附近的原文与上下文，标记真命中、误报和漏报。
3. 提炼最小规则或解析能力，避免只靠扩大关键词范围。
4. 将允许入库的去标识化片段加入`tests/fixtures/`，写对应回归测试。
5. 记录适用版本和不确定性。只有经过实际案例验证的规则才标记`case_verified`。
