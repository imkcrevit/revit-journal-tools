# 本地Journal查看器

产品入口是本地浏览器中的日志工作台。Python CLI提供启动与批量导出，解析器、分类器和磁盘索引可独立复用。

## 使用方式

```bash
revit-journal view /path/to/journals --recursive --encoding cp1252
```

浏览器打开终端给出的地址。`--port`设置端口，`--database`设置索引缓存位置，`--encoding`设置编码策略。默认`auto`逐文件判定（BOM→严格UTF-8→系统代码页超集，中文Windows为gb18030），全部失败时退化解码并标记；首批英/德文上传案例可用`cp1252`严格读取。上下文面板显示每个文件实际使用的编码与退化状态。

1. 在左侧搜索并选择日志文件。文件名下可见所属目录、大小和索引状态。
2. 按启动、系统数据、错误、API错误、操作内容等类型切换列表。
3. 输入关键词或词语前缀搜索当前分类，例如`ExceptionCode`、`GeomStepList`。
4. 点击记录查看前后各8行上下文、规则ID、编码和来源哈希。
5. 使用“跳至行”绕过分类和搜索条件，直接检查指定位置。

服务只监听`127.0.0.1`。本机运行时直接访问；在SSH服务器运行时，需要将实际服务端口转发到本机后再访问。当前没有公网发布、用户账户或浏览器上传接口。

## 分类含义

分类是记录内容标签，不表示已经识别了完整操作阶段，也不是事故根因。

| 分类 | 第一版范围 |
| --- | --- |
| 启动 | 会话开始、构建信息、初始化、外部应用启动等显式记录 |
| 系统数据 | 内存、图形资源、系统语言、版本、部分配置与许可信息 |
| 错误 | 除API错误外，被现有错误规则识别的记录 |
| API错误 | API_ERROR标记及花括号块续行，最多延续200行，并在新API/操作事件处结束 |
| 操作内容 | Jrn.Command、Jrn.Data、RibbonEvent及常见控件记录；支持下划线续行 |
| 警告 | DBG_WARN记录；更具体的错误规则可以将其归入错误 |
| API活动 | 未被归入启动或API错误的API_SUCCESS/API_INFO |
| 其他记录 | 当前尚未进一步分类的原文，仍被完整索引与检索 |

每行只分配一个主分类。顶部“错误相关记录”包括错误和API错误；API错误计数包含续行，因此不等于CLI按规则直接命中的候选数量。主Journal、Worker与精简副本分文件显示，不把重复副本当成独立事故。

行号统一按CRLF、LF、单独CR换行计数。真实案例中有混合换行：某些位置会与`rg -n`等仅按LF计行的输出相差若干行；查看器、CLI报告和行号跳转使用同一约定。

## 性能与完整性

SQLite保存完整解码行和分类，使用文件/行号、文件/分类/行号索引及[FTS5全文检索](https://www.sqlite.org/fts5.html)。API按游标返回最多200条，界面每次仅渲染100条；上下文单独按行号加载，不把整个大文件发送到浏览器。

搜索使用词语与最后一个词语的前缀匹配，不是任意字符串子串匹配；连续中文字符串的内部片段可能无法单独命中。日志列表预览上限700字符，上下文每行展示上限16,384字符，超出有提示，磁盘索引仍保存完整行。

索引在后台按文件大小从小到大建立，已完成的文件先可用。索引会占用额外磁盘空间。已完成索引依据来源路径、文件标识、大小、修改时间、编码和索引/规则版本重用，完成时记录完整源字节SHA-256。运行中源文件变化会提示缓存已旧，重启查看器会重建相关文件。

显式编码下的严格解码失败、超长行或源文件并发变化会使该文件进入失败状态（`auto`下的解码失败改为退化解码并逐行标记），不把部分索引当成完成数据。索引写入状态与查询分开处理，API只提供已完成文件的记录。原始Journal与压缩包不会被改写。

当前尚未实现拖放导入、跨文件统一时间线、完整多行堆栈事件模型、Windows安装包和真实Revit联动。已完成的离线验证与未完成的产品能力应分别描述。
