# 本地Journal查看器

同一个页面有两种入口：桌面窗口`revit-journal gui`（pywebview内嵌WebView2），以及浏览器中的`revit-journal view`。Python CLI提供启动与批量导出，解析器、分类器和磁盘索引可独立复用。

## 使用方式

```bash
revit-journal gui                                      # 桌面窗口；需要pip install "revit-journal-tools[desktop]"
revit-journal view /path/to/journals --recursive       # 浏览器
```

桌面窗口在本机启动同一个只读查看服务（优先使用端口8790，被占用时改用空闲端口），以`?desktop=1`加载页面。页面通过`window.pywebview.api`调用三个操作：`open_files`、`open_folder(recursive)`、`open_local`，分别弹出系统文件对话框、文件夹对话框或打开本机各版本Revit的Journals。新的输入替换整个工作区：先停止并等待当前索引任务，再登记、建立新索引；无法读取的路径逐条提示，其余照常打开。读取仍全部走下列HTTP接口。

页面布局：左侧工作区、段落列表、原文三栏，分隔条可用鼠标拖动或方向键调整，双击恢复默认；页面本身不滚动，只有文件列表、记录列表和原文各自滚动，宽度不小于900px时不出现横向滚动条。窗口宽度不超过1180px时分类片与工具栏收紧（更小的内边距与字号，计数变淡），来源子标签与分类片在同一区域内换行，工具栏按需换行；窗口高度低于760px时文件概览收为一行（文件名、路径、会话摘要按钮和四个计数），会话标签移到“会话摘要”按钮的提示中。1024×700窗口下分类片、工具栏、列头与列表前几行同时可见。宽度不超过900px时三栏改为上下排列，页面整体滚动。宽度、主题（跟随系统/浅色/深色）、语言（中文/English）、版本折叠与排序方式保存在页面的localStorage中。

语言：右上角切换中文/English，首次按系统语言选择。页面文字、分类、阶段、来源和编码依据由页面按键名翻译；会话摘要、会话级发现和错误提示由服务端按`lang=en`生成英文（`i18n.py`、`session_view.summary_lines(lang=)`、`summary.session_findings(lang=)`），Journal原文与路径不翻译。默认中文输出与改动前逐字相同；命令行与工单报告只有中文。`/api/session`另返回`refs`：每行摘要指向的主Journal行号，页面据此生成链接，不再在浏览器端用正则匹配。桌面窗口固定端口并保留WebView2用户数据（缓存目录的`webview`子目录），因此重启后仍然有效；浏览器中按地址分别保存。Ctrl+F搜索、Ctrl+G跳至行、Ctrl+O打开文件（桌面），列表中上下键逐项查看。

`view`在浏览器打开终端给出的地址。`--port`设置端口，`--database`设置索引缓存位置，`--encoding`设置编码策略。默认`auto`逐文件判定（BOM→严格UTF-8→Journal声明的界面语言对应的代码页→gb18030（须像中文）→系统代码页→cp1252），全部失败时退化解码并标记；判错时可显式指定，如`--encoding cp1252`。上下文与段落面板显示每个文件实际使用的编码、判定依据与退化状态。

1. 左侧按Revit版本分组（可折叠，“全部折叠/全部展开”），版本下按会话时间排序（“最新在前/最早在前”），每个会话列出它的文件；筛选文件名时展开所有匹配的版本。版本取所在的`Autodesk Revit <年份>`目录，不在该目录下的副本取Journal头部`Branch`/`Release`中的年份，都没有时归入“未知版本”；Worker日志随所属会话的主Journal归组。会话时间取主Journal记录的开始时间，尚未完成索引时用文件修改时间。文件下方显示类型、大小和索引状态（就绪后为行数）；标题下方显示所属会话、时长和结束状态。打开文件后自动显示第一个段落。
2. “段落”（默认）按事件列出，与`browse`相同：时间戳记录、API花括号、`Jrn.`续行、错误记录等组成一个段落，标出会话阶段；“折叠重复段落”把除时间戳与计数外完全相同的段落合为一项并显示“×N”，阶段下拉框只列该阶段的段落。“逐行”列出每一行原文。
3. 按启动、Add-in、退出、错误、API错误、操作内容、对话框等分类切换列表，段落与逐行视图使用同一组分类。段落视图中选中“Add-in”后才显示来源筛选“全部/Autodesk/第三方/来源待定”（只显示存在的来源），不再与Autodesk加载、第三方加载并列为三个重叠的分类；来源覆盖各种Add-in记录，包括`API_ERROR`加载失败，因此来源计数与分类计数有重叠。每条Add-in记录一行：来源标签代替记录分类，其后是种类标签（加载、服务、服务器、清单、外部事件、更新器、程序集、目录注册等，见[终端文档](terminal.md)的种类表）和名称，列标题为“来源/Add-in名称”；没有名称的记录在种类后显示原文标题，只有错误类记录另加分类标签。原文标题为“行号 · Add-in · 种类 · 来源”和Class，不再重复“Add-in加载”阶段。`Registered an external server`的API记录与紧随其后的空`'E`时间戳行、同一ServerId的`[Jrn.RegisterExternalServer]`合为一个段落。

   列表的列头可以点击（带下拉箭头的列头才有菜单）：菜单出现在列头下方，Esc、点击菜单外或完成选择后关闭，键盘可用上下键在选项间移动。“分类”列头列出全部分类及本文件的计数（段落视图为段落数，逐行视图为行数，全部文件搜索时不显示计数），单选，效果与点击分类片相同。Add-in分类及来源筛选下该列头为“来源”，列出全部、Autodesk、第三方、来源待定及计数，单选，效果与来源子标签相同。“Add-in名称”列头列出14种Add-in记录种类（加载、服务、服务器、清单等，见[终端文档](terminal.md)的种类表）及本文件计数，计数包含加载失败的API错误段落，为0的种类变淡；勾选后按“确定”只显示选中种类，“全选”“清空”批量勾选，全部勾选等于不筛选，一项都不选时不能确定。筛选生效时列头显示为“Add-in名称 · N种”。种类筛选只属于当前文件的Add-in视图：切换文件、离开Add-in分类或切换到逐行视图时清除；全部文件搜索不使用种类。

4. 输入关键词搜索，例如`ExceptionCode`、`GeomStepList`。空格分隔的多个词须出现在同一行，顺序不限（`Command Jrn`与`Jrn.Command`都能命中`Jrn.Command`所在行）；加英文双引号的`"open project"`是相邻短语；最后一个未加引号的词同时按前缀匹配，便于边输边搜。只含标点或符号的搜索词（如`}`）不参与分词，页面显示错误提示而不是空列表，列表保留上一次结果。段落视图中命中所在的段落只列一次，搜索时不折叠；底部“命中N行”统计整个文件中命中的行数，不是段落数（选了行分类时只统计该分类的行）。点击段落结果时，右侧从该段落的首个命中行开始显示并选中该行；列表、段落原文和上下文中每个搜索词的每次出现都会高亮（不区分大小写）。查询含中文、日文等连续文字时，页面提示这类文字按整段匹配。

   搜索框旁的“当前文件/全部文件”切换搜索范围（不保存，默认当前文件）。“全部文件”在所有已就绪的文件中搜索：每个文件一个标题行（会话、文件名、“命中N行”），下面列出该文件前3条命中行；底部显示“命中N行 · M个文件”，未完成索引、索引来自旧版本或源文件已变化的文件不参与搜索，计为“跳过K个”。点击命中行（或用上下键移到该行后按Enter）切换到该文件并定位到该行，范围回到当前文件，搜索词保留，因此列表即该文件的搜索结果。此模式下分页按钮不可用；Add-in、退出等行分类照常限定命中行，选中Add-in来源（段落专用筛选）时按全部分类搜索。

5. 点击段落查看它的完整原文（每次200行，可继续加载）、规则ID、阶段、折叠的全部起始行、编码和来源哈希；点击行查看前后各8行上下文。
6. 使用“跳至行”绕过分类和搜索条件，直接检查指定位置；段落视图中显示该行所在的段落并选中该行。
7. “会话摘要”显示与`revit-journal summary`相同的文字：版本、时长、结束状态、阶段、异常与崩溃、对话框、Add-in、侧车文件和会话级发现（均为候选）；含行号的行可点击，定位到主Journal中的位置。

只读接口：`/api/files`、`/api/events`、`/api/context`（逐行），`/api/blocks`、`/api/block`、`/api/block_at`、`/api/fold`（段落，内部调用`ViewerIndex.blocks`、`block_lines`、`block_at`、`fold_members`，标签与CLI列表同为`block_label`/`block_summary`），`/api/session`（`session_view.summary_lines`），`/api/search`（全部文件搜索，`q`、`category`、`per_file`，内部调用`ViewerIndex.search_workspace`；每个有命中的文件返回`hit_lines`与前`per_file`条命中行，行结构同`/api/events`，另有`total_lines`、`file_count`、`skipped`）。带`q`的`/api/events`、`/api/blocks`另返回`terms`（供高亮的词与短语）、`hit_lines`（整个文件的命中行数）和`hint`（仅含CJK的查询），`/api/blocks`的每个段落另有`hit_line`（段落内首个命中行）。`/api/blocks`的`kinds`为逗号分隔的Add-in记录种类（`load`、`service`、`server`等，空值表示不筛选），只在`category`为`addin`或来源筛选时生效，其他分类下忽略；未知种类返回400。`/api/files`每个文件的`block_counts`另含`kind_<种类>`段落计数。查询无效（空白、只含标点、参数越界）时返回400与错误文本，`lang=en`时错误与`hint`为英文。

服务只监听`127.0.0.1`。本机运行时直接访问；在SSH服务器运行时，需要将实际服务端口转发到本机后再访问。当前没有公网发布、用户账户或浏览器上传接口。

## 分类含义

分类是记录内容标签，启动、退出、其他记录另按所在阶段划分；分类不是事故根因。

| 分类 | 范围 |
| --- | --- |
| 启动 | 会话开始、构建信息、初始化等显式启动记录；以及第一次用户操作之前未被其他分类命中的行，包括内存采样、系统语言、配置与许可信息 |
| Add-in | 任何阶段的显式Add-in记录：`Starting External (DB) Application`加载记录及其花括号续行、`[Jrn.AddInManifest]`、`[Jrn.RegisterExternalServer]`、`Jrn.AddInEvent`、外部服务注册与注销、程序集加载到上下文、`Third Party Updater`等；加载失败仍为API错误 |
| 退出 | `ExitManagedInstance`、`finished recording journal file`、`License shutdown starting`、`journal(s) aged out`等显式退出记录；以及退出标记之后未被其他分类命中的行 |
| 错误 | 除API错误外，被现有错误规则识别的记录 |
| API错误 | API_ERROR标记及花括号块续行，最多延续200行，并在新API/操作事件处结束 |
| 操作内容 | Jrn.Command、Jrn.Data、RibbonEvent及常见控件记录；支持下划线续行 |
| 警告 | DBG_WARN记录；更具体的错误规则可以将其归入错误 |
| API活动 | 未被归入Add-in或API错误的API_SUCCESS/API_INFO |
| 对话框 | `TaskDialog "..."`提示与`Jrn.Data "TaskDialogResult"`答复及其续行 |
| 其他记录 | 会话中（第一次用户操作之后、退出之前）未被其他分类命中的行，包括`Delta VM`内存采样；空行；仍被完整索引与检索 |

启动、退出、其他记录的阶段与段落的会话阶段使用同一组标记：第一个非Revit自动写入的`Jrn.*`命令或打开文档结束启动期；`ExitManagedInstance`、`finished recording journal file`、`journal exit`、`License shutdown starting`进入退出期，之后不再回退。段落取首行分类，这三个位置性分类会被段内第一个其他分类覆盖。

每行只分配一个主分类。顶部“错误相关记录”包括错误和API错误；API错误计数包含续行，因此不等于CLI按规则直接命中的候选数量。主Journal、Worker与精简副本分文件显示，不把重复副本当成独立事故。

行号统一按CRLF、LF、单独CR换行计数。真实案例中有混合换行：某些位置会与`rg -n`等仅按LF计行的输出相差若干行；查看器、CLI报告和行号跳转使用同一约定。

## 性能与完整性

SQLite保存每行的分类与在源文件中的字节位置（`--store text`时保存完整解码行），使用文件/行号、文件/分类/行号索引及每个文件一张不存内容的[FTS5全文检索](https://www.sqlite.org/fts5.html)表。偏移方式下原文按位置从源文件读取，源文件须保持原位不变，读取前核对大小、修改时间和文件标识。API按游标返回最多200条，界面每次仅渲染100条；上下文单独按行号加载，不把整个大文件发送到浏览器。

搜索按FTS5词语匹配：多个词同时包含，引号内为相邻短语，最后一个未加引号的词按前缀匹配；不是任意字符串子串匹配（`rror`不会命中`ERROR`），标点不参与分词。unicode61分词把一段连续的中文、日文等文字当作一个词，因此只能从这段文字的开头查找，内部片段无法单独命中。命中行号与命中行数在查询时计算，不改变索引结构。日志列表预览上限700字符，上下文每行展示上限16,384字符，超出有提示，磁盘索引仍保存完整行。

索引在后台建立，已完成的文件先可用。多个文件且总量不小于2MB时，由子进程并行解析（默认逻辑核数减1、最多8个，大文件优先以缩短总耗时），每个子进程只写自己的临时库；主进程逐个文件把结果复制进索引，一个文件一个事务，并在该事务内批量建立全文索引。单个文件或总量较小时在本进程内顺序建立。文件在事务提交前不可查询，建立中的进度保存在内存中供界面显示。索引会占用额外磁盘空间：本机实测偏移方式为源文件的1.4–2.2倍，`--store text`为3.1–3.6倍。已完成索引依据来源路径、文件标识、大小、修改时间、编码和索引/规则版本重用，完成时记录完整源字节SHA-256。运行中源文件变化会提示缓存已旧，重启查看器会重建相关文件。

显式编码下的严格解码失败、超长行或源文件并发变化会使该文件进入失败状态（`auto`下的解码失败改为退化解码并逐行标记），不把部分索引当成完成数据。索引写入状态与查询分开处理，API只提供已完成文件的记录。原始Journal与压缩包不会被改写。

当前尚未实现拖放导入、跨文件统一时间线、Web中的折叠展开与Add-in名称前缀筛选（终端`v`与`--addin-prefix`已有）、Windows安装包和真实Revit联动。已完成的离线验证与未完成的产品能力应分别描述。
